## 1. 项目概况

- 用途：《竞拍之王》游戏的红品估值与出价助手。用户每场输入「红品平均格数」及
  可选已知红品信息，系统反推格数组合候选、估算红品与全场总价值、给出估值区间、
  推荐出价与风险等级；结算后录入真值并（未来）持续学习。

- 当前数据：图鉴 188 件（`catalog_items`）、历史对局 49 局（`game_records`）、
  ML 训练样本 44 局。
- 运行方式：双击根目录 `启动.bat`（等价于 `python backend/run.py`），
  前端 dist 由后端静态托管，访问 `http://127.0.0.1:8000`。
- 应用当前正在运行（端口 8000）。重启方式：结束 `python backend\run.py` 进程后
  重新启动即可。

## 3. 估值引擎核心逻辑（engine.py）

### 3.1 输入

- 必填：`red_avg`（红品平均格数）。
- 可选：`red_count_est`、`known_items`（多件已知红品，每件含 name/size/value）、
  其他品质格数、`margin`（默认 0.84）、`min_bid`、棋盘 `board` 等。
- 兼容旧字段 `known_size` / `known_value`（单件已知红品）。

### 3.2 均格归一化与候选匹配（重要口径）

- 输入均格先四舍五入归一到 1 位小数（如 2.25 → 2.2，并给出警告）。
- **候选匹配不是"四舍五入"语义**：游戏显示的均格不按四舍五入，
  因此 `find_candidates` 使用宽容区间 `c <= a/b <= c+0.05`。
  例如均格 3.7 会保留 15 格/4 件（8+4+1+2，实际 3.75）。
- 候选枚举范围：总格数 ≤ 50、件数 ≤ 80；可用格数来自图鉴实际存在的格数
  （1/2/3/4/6/8/9/12/15/16）。
- 候选按「件数历史先验 + 用户预估件数」排序，取前 8 个。

### 3.3 组合采样

- 用有序计数 DP（`_count_dp`）统计组合数，再按权重随机采样互不重复的组合，
  默认每个候选采样 800 组、每组 MC 抽 8 次（seed 42，结果确定）。
- `must_include` 支持**多重集**：已知红品的格数必须全部出现在组合里
  （例如已知 8+2 格，组合必须同时含一个 8 和一个 2）。

### 3.4 价格基准（重要口径）

- **以 Excel 图鉴价为权威来源**（用户明确要求）。
- 各格数统计使用图鉴价格池的 **10% 截尾**版本（`_trimmed_pool`）：
  均值、p10/p90/中位数、抽样池全部来自截尾后的价格池，
  避免个别异常高价（如 1 格"非洲之心"1511 万、4 格"江山永固金樽"2329 万）把期望顶飞。
- 不再使用旧对局记录的经验均值作为 EV 基准（旧数据与当前图鉴价格体系不一致）。

### 3.5 已知红品计入期望

- 已知藏品的**实际价值**会顶替该格数平均价计入期望（`known_adjust`）：
  `known_adjust = sum(已知价值) - sum(对应格数平均价)`。
- 保证：每个候选的「红品期望」≥ 已知藏品价值之和；
  每个候选展示的组合样例都包含全部已知格数。
- 候选过滤：总格数/件数无法同时容纳全部已知格数的候选会被剔除并提示。

### 3.6 聚合与区间

- 各候选按分数加权聚合；**区间抽样按"每候选等权（分数）"**计算
  （每个候选的抽样次数除以自身数量再加权），保证
  `p10 ≤ p50 ≤ 期望 ≤ p90` 恒成立（此前组合多的候选会被重复加权导致 p10>期望）。

### 3.7 全场估值与出价

- 填了其他品质格数 →「逐品质细分」模式；否则按实测倍率
  `全场总价值 = 红品价值 × 1.76`（来自历史对局均值，兜底 1.36）。
- 推荐出价 = 全场期望 × margin（默认 0.84）。
- 最低可接受价 = 全场 p10 × margin（或用户填的 `min_bid`）。
- 风险等级 = 区间倍数（p90 / p10）：<3 低、3~8 中、≥8 高。

## 4. ML 融合现状（重要）

- 模型 `ml_full.joblib`：2026-08-12 22:15 训练，44 个样本，**未重新训练**。
- 训练方式：以规则估值为先验的 log 残差回归集成
  （BayesianRidge + GaussianProcess + HistGradientBoosting）。
- **训练真值仍是旧价格体系**：历史对局 red_value/full_value 与新 Excel 规则期望
  的中位残差约 -0.83（旧真值平均只有新规则期望的 43%）。
- 因此**当前不要直接重训**——重训会让模型学会"规则算高了"，把期望压回旧水平。
- 当前融合策略（main.py `_merge_ml`）：
  - 有已知藏品价值时：ML 与规则 **50/50 融合**（避免旧模型单方面压低），
    并标记 `ml.blended = true`；出价/最低价基于融合后的全场估值。
  - 没有已知藏品价值时：ML 仍全量覆盖规则估值（可能偏低，属已知现象）。
- 用户已确认维持现状；后续若要让模型跟上 Excel 价格，
  需先按最新图鉴价刷新 `game_records` 的 red_value/full_value 再重训。

## 5. 前端功能与近期改动

1. **浅色主题**：`tailwind.config.js` 的 `ink` 色板改为浅色；
   `index.css` 正文/卡片/输入框/按钮/滚动条全部适配；各页面文字颜色类
   从浅色档换为深色档（全局机械替换过），强调色 300 档 → 600 档。
2. **均格输入强制 1 位小数**：step=0.1、失焦归一、OCR 填入 toFixed(1)，
   后端兜底 round(c,1) 并警告。
3. **多已知红品**：`known_items` 动态列表，每行 = 图鉴下拉 + 格数 + 价值 +
   「识别藏品」；可增删；候选卡片显示「其余藏品期望 ≈ X」。
4. **识别藏品新交互**（backend `identify_item`）：
   - 只填格数：返回该格数全部图鉴藏品，按**系统价从低到高**；
   - 填了价格：返回该格数全部藏品，按 **|价格差| 从小到大**（无 ±2% 过滤），
     每项显示价值与相差金额/百分比；
   - **每个藏品只返回一条**（系统价 `value`），不再返回现价/交易行价
     （`current_value`）的重复条目；
   - 只有一个匹配时自动填入，多个时展示按钮，点选后自动填充该行。
5. **千位分隔符**：已知红品价值输入实时显示 9,000,000 形式，解析时自动去逗号。
6. **候选锁定**：点击候选可锁定并按该组合重算估值与出价；
   候选列表始终完整显示，锁定仅影响计算；「恢复综合估值」一键回到加权结果。
7. 估价结果：红品/全场期望与 p10–p90 区间、推荐出价、最低可接受价、风险徽章
   （显示「区间倍数 ×N」）、历史同类局参考表。

## 6. 已知问题 / 注意事项

- **AWM 价格不符**：用户要求"AWM 以 60 万为准"，但图鉴里 `AWM枪械藏品`
  （12 格）当前为 258 万；按 60 万识别时它不会排在前面。若用户确认，
  需在「图鉴管理」把该价格改为 60 万（用户未最终确认，先记录）。
- **无已知藏品时 ML 会压低期望**：旧训练数据所致，用户已选择维持现状。
- **图鉴中个别异常高价**（非洲之心 1511 万、江山永固金樽 2329 万等）：
  已通过 10% 截尾处理，不影响统计口径；若这些价格本身是错的，
  应在图鉴管理修正后再评估是否需要调整截尾策略。
- **OCR / 结算识别 / GPU 加速**：用户明确暂不处理，先不要动 `ocr.py` 的
  结算识别与 GPU 相关逻辑。
- 旧历史对局（1-31 局等）价格与当前图鉴价格体系不一致，会影响
  「历史同类局参考」与 ML 训练真值（见第 4 节）。

## 9. 给下一个 Agent 的建议

1. 先跑一遍 `pytest` 和一次 `POST /api/estimate` 确认环境正常。
2. 任何"期望/出价偏低"类问题，先检查是否由 ML 融合或旧历史真值引起，
   不要直接重训（见第 4 节）。
3. 修改估值口径时，保持 `p10 ≤ 期望 ≤ p90`、候选期望 ≥ 已知藏品价值
   这两个不变量。
4. 界面改动后必须重新构建 `frontend/dist` 并重启服务。
5. 数据库是 `data/bidking.db`，图鉴数据以 Excel 为准；改动价格口径前
   先和用户确认。
